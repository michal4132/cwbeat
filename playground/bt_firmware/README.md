# Go 4 BT startup clock patch

It reuses the inherited PLL during compatible cold startup, avoiding the native
temporary switch to the crystal and PLL restart that disturbed USB. Native
final clock selection, rate bookkeeping and peripheral/audio setup still run.
Any guard mismatch takes the original initialization and failure path.

This is a separate BT image patch. Building or flashing the TOP application
does not install it.

## Contents

| File                            | Purpose                                                               |
| ------------------------------- | --------------------------------------------------------------------- |
| `adopt_live_pll.S`, `layout.ld` | Exact assembly and placement of the tested hook and guarded stub      |
| `manifest.json`                 | Original/patched byte spans and expected firmware hashes              |
| `build.py`                      | Assemble and verify the generated bytes against the manifest          |
| `audit.py`                      | Compare original and patched native clock routines in emulation       |
| `bt_patch.py`                   | Prepare an offline plan, apply it through SBL, or restore original BT |
| `dump.py`                       | Read and CRC-verify a full device backup through SBL                  |
| `test_dump.py`                  | Offline dump and failure-path tests with fake hardware               |
| `test_bt_patch.py`              | Offline transaction and failure-path tests with fake hardware         |

The source firmware and device-specific backup are external inputs. Keep full
images, generated plans and transaction records outside the checkout. The
manifest contains only the small patch spans, not a complete vendor image.

## Build and audit

Use Python with the dependencies in `requirements.txt`, plus a GNU ARM embedded
toolchain. From the repository root, with your Python environment activated:

```sh
python -m pip install -r playground/bt_firmware/requirements.txt
python playground/bt_firmware/build.py \
  --toolchain-prefix /path/to/bin/arm-zephyr-eabi- \
  --output-dir /tmp/go4-bt-clock-build
python playground/bt_firmware/audit.py \
  --backup /path/to/verified-original-4MiB-backup.bin \
  --build-dir /tmp/go4-bt-clock-build \
  --output /tmp/go4-bt-clock-proof.json
```

The build must reproduce the four-byte hook at BT CPU address `0x7c4a4` and
276-byte stub at `0xd8000`. These map to physical flash `0xcc4a4` and `0x128000`.
No original code or tables are relocated. The final word at `0xdcffc` is
unchanged; it has not been established to be a checksum.

The native routine audit covers compatible adoption, rejection of changed
records/registers, readiness timeout, preserved registers and original fallback
behavior. Emulation checks instructions and modeled register writes; it does
not establish physical PLL timing. Hardware results and limits are in the
external investigation report (not included in this checkout).

Run the offline transaction tests against the same external backup:

```sh
python -B playground/bt_firmware/test_bt_patch.py \
  --backup /path/to/verified-original-4MiB-backup.bin
```

These use fake hardware and exercise byte/CRC validation, protected regions,
write ordering, failed writes, rollback checks and serial cleanup on failures.

## Exact supported source

The tooling deliberately accepts only the original verified 4 MiB backup used
for this experiment and the matching device flash identity. It is not a generic
patcher for other Go 4 firmware revisions or backups with different settings.

investigation report's verified recovery material. That report is not included

at the repository root, with its reviewed source hash checked before use.

## Dump current flash

With dependencies installed, enter SBL USB recovery (`0ac8:38b9`) and close
the serial console. On CWbeat firmware with the USB shell, run `power recovery`
and wait for USB to re-enumerate (about 32 seconds). From the repository root:

```sh
python3 playground/bt_firmware/dump.py \
  --port /dev/cu.usbmodem1101 \
  --output /tmp/go4-flash-dump
```

Use the actual recovery port and a new output directory outside the repository.
The script checks the experiment device's SBL and flash identity, reads all
4 MiB, and compares native flash CRCs before and after the read. It saves
`backup.bin` and `result.json`, including the SHA-256 and `matches_patch_source`.
It does not write device flash or reset the device. Move the backup to durable
external storage if you need to keep it beyond temporary-directory cleanup.

A dump captures the current firmware and settings; it does not recreate the
original image. Only when `matches_patch_source` is true can this dump be used
as `--backup /tmp/go4-flash-dump/backup.bin` for the patch plan below. Otherwise,
you still need the exact original backup; do not bypass the source checks.

Run the dump tests without hardware or a vendor backup:

```sh
python3 -B playground/bt_firmware/test_dump.py
```

## Plan, apply and restore

Plan creation is offline. It validates the original image and writes the source,
candidate, manifest and plan into a new output directory:

```sh
python playground/bt_firmware/bt_patch.py plan \
  --backup /path/to/verified-original-4MiB-backup.bin \
  --manifest playground/bt_firmware/manifest.json \
  --output /tmp/go4-bt-clock-plan
```

Plans pin the helper and manifest hashes. Regenerate a plan with this repository
version; plans made by the earlier external helper are intentionally rejected.

For an unpatched device whose complete live flash exactly matches that backup,
enter SBL recovery (`0ac8:38b9`), release the serial console, then run:

```sh
python playground/bt_firmware/bt_patch.py apply \
  --plan /tmp/go4-bt-clock-plan/plan.json \
  --port /dev/cu.usbmodem1101 \
  --output /tmp/go4-bt-clock-apply
```

Apply changes only BT sectors `0xcc000` and `0x128000`, then the BT checksum
fields in metadata mirror `0x1000` and primary `0`. It verifies BT before
committing metadata, then the entire flash. Journals and readbacks are saved
before mutation. The command leaves the device in SBL; it does not reset or
retry automatically. The already-patched board will fail the original-source
check, as intended.

Restore requires the exact patched BT allocation and metadata from the plan.
The current TOP image without USB recovery has different metadata. Before BT
restore, use the guarded TOP-only flasher to restore the earlier TOP payload
with SHA-256 `94eef69169ded4b5adc444bdbc66532b8c801580cccefcf07ec9948a6110a451`,
leaving the device in SBL. This restores the metadata expected by the BT plan.
Then:

```sh
python playground/bt_firmware/bt_patch.py restore \
  --plan /tmp/go4-bt-clock-plan/plan.json \
  --port /dev/cu.usbmodem1101 \
  --output /tmp/go4-bt-clock-restore
```

Restore preserves unrelated current settings. An interrupted or partial write
does not qualify for ordinary restore: preserve the journal and readbacks for
inspection before attempting any repair. Do not bypass source, protocol or
metadata guards to reuse a mismatched plan.
